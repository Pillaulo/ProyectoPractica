# ADR-002: Fragmentación como Servicio de Dominio

**Estado:** Aceptado
**Fecha:** Marzo 2026
**Contexto del decisor:** Arquitecto de Software Senior

---

## Contexto

Los cuentos generados por el LLM llegan como un bloque de texto completo. Necesitamos dividirlos en fragmentos para la lectura progresiva. La pregunta es: ¿dónde vive la lógica de fragmentación?

### Opciones

1. **En el LLM**: pedir al modelo que genere el cuento ya fragmentado (con delimitadores).
2. **En el adaptador LLM**: el adaptador fragmenta el texto después de recibirlo.
3. **En el caso de uso**: la lógica de partición vive en la capa de aplicación.
4. **En un servicio de dominio**: la fragmentación es una regla de negocio pura.

## Decisión

La fragmentación se implementa como un **servicio de dominio** (`FragmentationService`) en `domain/services/`.

## Justificación

| Opción | Ventaja | Problema |
|--------|---------|----------|
| En el LLM | Menos código propio | Resultado impredecible; el LLM podría ignorar la instrucción, variar el formato, o generar fragmentos desiguales. Sin control determinista. |
| En el adaptador | Cercano al punto de generación | Viola la arquitectura: la fragmentación es regla de negocio (depende del nivel lector), no es responsabilidad del adaptador de infraestructura. |
| En el caso de uso | Accesible y fácil | Los casos de uso deben orquestar, no contener lógica de negocio compleja. Si otro caso de uso necesita fragmentar (ej: re-fragmentar un cuento existente), duplicaría lógica. |
| **Servicio de dominio** | Puro, testeable, reutilizable | Requiere un archivo adicional. |

### Razones clave

- La fragmentación depende exclusivamente del **nivel lector** (un concepto de dominio), no de la infraestructura.
- Es una función pura: `texto + nivel → fragmentos`. Sin efectos secundarios.
- Es testeable al 100% sin mocks: se le pasa un string y un enum, se verifica la salida.
- Si en el futuro se quiere re-fragmentar un cuento existente a otro nivel, el servicio se reutiliza sin duplicar código.

## Consecuencias

**Positivas:**
- Lógica de fragmentación con cobertura de tests completa.
- Reutilizable desde cualquier caso de uso.
- Independiente del proveedor de LLM.
- Parámetros de fragmentación (longitud máxima por nivel) fáciles de ajustar.

**Negativas:**
- El LLM podría generar texto con estructura natural (párrafos) que el fragmentador ignora. Aceptamos esto porque la consistencia y el control determinista son prioritarios sobre la "naturalidad" del corte.

## Algoritmo de fragmentación (alto nivel)

1. Dividir el texto en oraciones (split por `.`, `!`, `?` preservando puntuación).
2. Agrupar oraciones en fragmentos sin exceder el límite de palabras del nivel.
3. Si una oración individual excede el límite, se incluye como fragmento propio.
4. Retornar lista de `Fragment` con `order` secuencial.
